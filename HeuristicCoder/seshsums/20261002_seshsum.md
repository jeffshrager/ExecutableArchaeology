# Session Summary — 2026-10-01 to 2026-10-02

## Goal

Start the executable-archaeology treatment of Simon's **Heuristic Coder** (Simon
Papers, Box 14, FF965, listing dated 7/16/61; companion paper: Simon 1963 JACM,

## Work Done

### 1. Interpreter decision

Jeff decided to run the program on his Common Lisp IPL-V, not Beyer's 1620. Changes
were expected, and they risked breaking LT, so the interpreter was **copied** into this
project (`lisp/iplv.lisp`, from `jeffshrager/IPL-V@792cb15`). Jeff's decisions: the copy
moves forward on its own, with no change log, no overlay file, and no worry about
retrofitting; checking it against LT can come later. The first improvement is that it
**reads 80-column IPL-V cards directly**, without converting to `.liplv`.

### 2. Native card reader (`lisp/iplv.lisp`)

- `load-ipl` looks at the first line of the file. If it starts with `(:` the file is
  read as `.liplv`; anything else is read as cards (`next-card-row` / `read-card`).
  Cards come out as the same 9-field rows as before, so `save-cells` etc. are unchanged.
- Columns: comment 1-40, type 41, name 43-47, sign 48, PQ 49-50, SYMB 51-55,
  LINK 57-61, comment 62-70, **id 71-80**. The id was moved from 73-80 so the
  listing's long ids such as `T041 220 C` fit.
- A blank PQ is `00`. If only one PQ column is blank it counts as 0 (` 1` becomes `01`).
- Integer terms (PQ 01) are read from anywhere in cols 51-61 with the blanks removed,
  and the sign comes from col 48. **This differs from Beyer's loader**, which reads blanks
  as zeros, i.e. it wants the value right-justified. The 7094 `Acker.Ipl` deck puts the
  value at col 57.
- Alphanumeric terms (PQ 21) keep leading blanks. An all-blank term becomes `" "`, as in
  LTFixed.
- Comment cards (type 1), title cards (type 9) and blank cards are skipped.
- The auto-run `simple.liplv` block at the end of the file was quoted out.
- Verified: `tests/Acker.Ipl` gives A(3,4)=125 (that deck uses N=4) and
  `tests/Ackermann.liplv` gives 61. The 2840-line `LT/LT.iplv` card deck loads fully and
  starts at X1, then fails at runtime in J10 called from Q7. That was expected and is out
  of scope, since LTFixed holds the fixes. Its 3 missing-local warnings also appear with
  LTFixed, so they come from the deck, not the reader.

### 3. Getting at the scan

- `brew install poppler` **failed**: Homebrew wants newer Command Line Tools than this
  macOS 13 machine has. The Read tool's PDF rendering also needs poppler.
- Workaround: each scan page is one embedded JPEG (1880x2444). They were extracted with
  `qpdf --show-pages --with-images` + `qpdf --show-object=N --raw-stream-data` and
  shrunk with `sips`/ImageMagick. The 1963 paper's images are in a format I couldn't
  render ("data"), so it is **not read yet**.
- `PAGEMAP.md`: page-by-page map of the 95 pages and their contents.

### 4. Transcription (`transcription/`, `heuristic.card`)

- `transcription/pNN.txt` has one card per line as `|`-separated fields. The full
  8-field form is `comment|type|name|sign|pq|symb|link|id`; the short 6-field form is
  `comment|name|pq|symb|link|id`. `#` lines are transcriber notes.
  `build.py` builds `heuristic.card`, skipping p41.
- **All 94 distinct pages transcribed: 4473 cards.** The pencilled total on page 1 is
  "4464".
- Checks: within every routine, ids increase by 10 with no gaps or duplicates, and every
  page boundary either continues the sequence or starts a new routine. The transcription
  has **not** been proofread a second time against the scan; I read it by eye, zooming
  in on unclear spots.

## Issues / Open Questions (from the listing)

1. **No start card.** The deck ends at `X199 110 D`, and the run was presumably started
   by a separate card. We need to supply one; `T1` or `R0` look like drivers, but that is
   a guess.
2. **Pages 40 and 41 are the same page scanned twice**, confirmed by eye and by page 42
   continuing at `U133 640`.
3. **Two spellings of locals.** Old style `90`, `910` and new style `9-0`, `9-10`. U199
   uses both for the same labels (`9-10`/`910`, `9-12`/`912`), so the loader must treat
   them as one symbol. The current reader treats anything starting with 9 as local but
   does **not** normalize the spellings.
4. **Header cards.** `000 695` is type 5 with PQ 30, "HEADER--MACHINE LANGUAGE" (P=3
   means machine-code input mode, yet ordinary IPL routines follow). Section C has PQ
   ` 5` (Q=5: data, internal symbols are machine addresses) and section D has PQ ` 1`.
   The Lisp loader only knows Q=0 and Q=1 headers.
5. **Type-2 region and type-3 block cards** (pp. 1-2, including "RESERVE PRINT LINE
   L101"): the Lisp loader ignores them. Print lines L101/T100 may matter for J154-J161.
6. **Region "long dash".** The type-2 card `000 240` names a region printed as a long
   dash, separate from the `-` region at `000 260`. It may be a different character
   (blank?). There is no matching type-3 card.
7. **Unreachable or odd cards:**
   - T79: cards 030-070 follow a terminating `0` with no name. The faint "T81" in the
     name column is bleed-through.
   - `T049 090 C`: a comment-only unnamed cell after T49's terminating 0.
   - `T106 000` is printed with type 5, though it is only a comment.
   - `U080 010`: the head's SYMB is U80 itself.
   - `A113 080` has no terminating LINK 0.
   - `L130 080` prints as `0.`.
8. **Pencil fixes are recorded but not applied:**
   - U135 150 has a hand-inserted `30H0` before `70J31`.
   - X176 has a proposed `X32 X38` pair.
   - U153/U154 carry extensive notes, e.g. "should be X41 of X71 of (2), probably X170",
     "has lost...", "must stop?".
   - U155 310 has `70J7` circled.
   - Smaller marks elsewhere.

   These are the original debuggers' notes and are likely real bug reports.
9. **Unclear readings to recheck:**
   - Sign columns on integer terms.
   - Trailing blanks in 21-terms, which can't be seen in a listing (e.g. `X111` "ALUE",
     "D OF").
   - `U031 020`, where a ghost "70" was rejected.
   - `U055 110` (SYMB 0 vs LINK 0).
   - `T073 160` (lone `-` SYMB).
10. **J-functions likely missing** from the Lisp interpreter (known list), plus the ones
    used here: J83 (U73), J101, J118, J147/J149/J150 (trace marking), J165/J166 (T99
    save/restart), J180-J186 (line read), and probably more. Not yet surveyed
    systematically.

## Part 2 (same day): loading and running

### Loader fixes (`lisp/iplv.lisp`)
- A blank SYMB and a blank LINK on the same card both mean the next card
  (`70 <blank> <blank>`, T102 090).
- Blanks on a list's last card mean 0 (e.g. the one-card working cells T10, T191).
- Old-style locals `9n` are read as `9-n`; a lone `9` is the internal symbol 9.
- Header Q parity: even Q means routines, odd Q means data (section C uses Q=5). P is ignored.

### The run
- The 1963 paper (OCR text layer, extracted from the CCITT PDF) identifies the deck's
  test problems: X105 = J3 SET SIGNAL MINUS (state description), X106/X107 = REPLACE
  and LOAD, X100-X102 = INSERT AT END OF VALUE LIST (functional description), and
  X180-X182 = J77's flow diagram. **T1 runs exactly these**, so `adapt.py` adds a
  start card for T1. The paper cites RAND P-2349 (June 1961), which includes "a listing
  of the program as of June 1961", i.e. this scan.
- **U126 is missing from the listing** (U128 calls it to enter a DSCN in the print
  line). `adapt.py` adds a short **reconstruction**, clearly marked as such.
- Results (`run/t1.txt`, from `./run.sh`):
  - X100 compiles to `J13 J52 11W2 11W0 J10 11W1 J65 J32 0`, **identical to the
    paper**, and the intermediate stages that are printed match the paper's steps.
  - The J77 flow diagram (segments J77/90/92/91 with P=7 branches) **matches the
    paper**, and J77 is recompiled from its segments.
  - X105 (J3) does **not** compile in the faithful run. U136 always prefers the DSCN;
    U134 finds no compiled routine with process X113, U138 reports no progress, and
    U135 quits. This appears to be what the listing does, not an interpreter bug.
  - Experiment `heuristic-run-sdsc.card` erases X105's DSCN first. The state
    description compiler (U140 → X7 → U141 → U150/U153/U154 → U155) then compiles
    J3 to `10J3 20H5 0`, **the paper's code**.

### Interpreter J's added or fixed
- Added: J12, J13, J61, J69, J70, J83, J101 (head marking emulated), J118, J149
  (no-op), J150, J165 (no-op). Probed with `lisp/tests/jprobe.card`.
- Fixed:
  - **numset**: Q=1 was outside the `setf`, so every computed integer printed as 0.
  - **J62**: it tested cell (1) itself and never tested the last cell.
  - **J68**: deleting a final symbol did nothing. It now unlinks the cell, as J60
    does with a private termination cell.
  - **J114**: it now compares alphanumeric terms.
- Ackermann still passes (card 125, liplv 61). **LT has not been rechecked**: the J62,
  J68 and numset fixes change behavior LT may have depended on.

### New issues
