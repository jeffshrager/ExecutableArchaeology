# Session Summary — 2026-10-15: critical review of the Lisp IPL-V interpreter

## Goal

Jeff asked for a critical analysis of `IPL-V/iplv.lisp` and proposed steps to improve it, plus
an opinion on whether to rework it completely. **This session was review only. No interpreter
code was changed.** The result is saved as `IPL-V/IMPROVEMENT_PLAN.md` for later. It was not
executed, for lack of credits.

## Findings (details in `IPL-V/IMPROVEMENT_PLAN.md`)

- **The most serious bug:** `ipl-string-equal` ignores trailing zeros. Verified in SBCL:
  `Q1`=`Q10`, `K2`=`K20`, `1`=`100`, and generated names `9-123`=`9-1230` all compare equal.
  It is used by J2, J10/J11, J62, J69, J77 and J181. LT uses both `Q1` and `Q10`-`Q19` as
  attributes, and works by luck of ordering.
- Other confirmed bugs:
  - J66 starts its search at the head, and J63/J65/J66 don't set H5.
  - J17 reads `W10`+ as `W1`.
  - J166 leaks an H0 entry.
  - The J183/J184 scanner never examines column 80.
  - J181 pushes `" "` for a blank field and uses LT-only regional characters.
  - J182 handles alphanumeric terms only.
  - J126 and `w25-init` create cells with the wrong PQ.
  - J137 is defined twice.
  - J130/J132 decide regional/local/internal by whether the name contains `-`.
- Architecture:
  - J arguments come from `function-lambda-expression`, which is why `(debug 3)` is needed.
  - Every J call walks the whole H0 stack.
  - Per-cycle history grows without bound.
  - Errors use `break`.
  - `load-ipl` defaults to `:adv-limit 100`.
  - There is no erasure and no available space.
  - There is no unified regression suite.

## Recommendation (Jeff's question: rework or keep?)

Keep it and refactor in place. The executor is a faithful, readable implementation of the
manual's interpretation cycle, and the J library holds knowledge checked against real programs.
The structural flaw is the memory model: cells are structs keyed by name strings, rather
than words at addresses. Most of the bugs come from that. Order:
1. Build a regression harness covering Ackermann, LT, the Heuristic Coder, the annexer and
   Yngve.
2. Fix the bugs within the current model, starting with symbol equality.
3. Optionally, replace only the memory layer behind a small API.

A full rewrite only pays off if the goal changes, for example to timing-faithful 7090
emulation.
