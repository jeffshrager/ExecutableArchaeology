### 2. EPAM: sources sorted out

- **New scan:** Jeff added `EPAM/EPAM_sc0340_1986-052_b56_f2.pdf` (Feigenbaum papers, Stanford SC0340,
  box 56, folder 2; 68 pp.) and its layout OCR `.txt`. It is an *assembled* listing (machine
  addresses, IDs like `F013-0010`): the experiment environment of a later EPAM that actually ran.
  - routines F13-F31 ("RECORD NEW RESPONSE", "RECITE SERIAL LIST"), T4/T5 (tasks), Q2-Q38 letter
    tests, K/L/N/P/B data;
  - its F13 calls D21/D23/F1. **Deferred**: Jeff wants EPAM II in a reasonable state first.
- **`EPAMFixed.liplv`** (from the archived IPL-V repo) is EPAM II, transcribed from the
  **appendix of RAND P-1817** (Feigenbaum, *An Information Processing Theory of Verbal Learning*,
  9 Oct 1959). The appendix has the listing's IDs (`CAPL01`, `D00 01`, ...).
- **EPAM II was never run.** P-1817 p. 85: "the program has been simulated by hand... the IPL-V
  computer is not yet fully completed." So there is no driver in the code, and the start card `Z1`
  that an earlier transcriber added is just a net test.
- **What it should do is in P-1817.** §4.1: serial anticipation of List A (KAG LUK RIL PEM ROM TIL)
  and paired associates. Figs. 4.1/4.2 give the hand simulation trial by trial.
- **Tools:** there is no poppler. pypdf and pillow were installed in a scratchpad venv; Homebrew's
  Python refuses `--user` installs (PEP 668). Page images come from `PdfReader.pages[i].images`.

### 4. Making it run (`a7d239a`, `ac728cb`)

- **Call graph:** EPAMFixed has no top-level routine. Its roots are D0 (spelt `DO`), D9 (spelt
  `09`), D22 ("RECOGNIZES AND WRITES A STIMULUS"), E12, Q1, P0 (spelt `PO`) and the integers.
  J190-J199 are *defined by EPAM* (`10Wn E13`, "advance Wn"), so they are not missing J's.
- **`make_run.py`** builds `epam2-run.card`:
  - `0000` → `0` (the card reader takes only `0`/blank as termination);
  - leading zeros dropped (U0002 = U2: defined U0002, referenced U2; this settles OPEN_ISSUES #13
    for this listing);
  - `DO`→D0, `09`→D9, `PO`→P0, confirmed by card IDs;
  - P0 is defined twice in the listing (both ID P0001): N1 N3 N2 and N1. `--p0 lines` (the
    default, §4.1) or `single`;
  - N0-N20 in a type-5 data section;
  - `*0`, E13's scratch cell, defined (the interpreter auto-creates only letter+digit regionals);
  - the added Z1 start card dropped; a driver deck is appended.
- **The D0 patch:** D0 always "ASSIGN[S] TRACKING LIST TO RESPONSE" with J11. In the letter
  dictionary X0, responses are alphanumeric data terms (X1 → L1 = "A"), which have no description
  list. This is a latent EPAM II bug that hand simulation never hit. The patch is 3 cards: J131,
  then skip the J11 if the response is a data term.
- **Transcription corrections** (`EPAM/CORRECTIONS.md`), checked against page images:
  - Q1 (the code for A, the only letter code in the listing) is 10001100010111, per p. 149 and
    the text p. 71. The transcription had J5s and two swapped bits.
  - L26 is `21 Z` (was `Z0`, with a `+0` remark).
- **My mistake, retracted:** I briefly reported six "transcription errors" in D0 (J1→J4, J7→J3).
  They were caused by a bug in my own Q1-fixing code in `make_run.py`, which overwrote every
  single-digit J symbol. The transcription had them right. After that, Jeff chose to check the
  transcription only when a run points to a problem.
- **The letter net U1** (26 terminals X1-X26 → L1-L26 via X0) tests only line 1, bits 1-14. Z0
  takes the minus branch on J3 = 1. A's code sorts to X1. This means the missing letter codes can
  be reconstructed from U1's paths.
- **Interpreter fix** (`ac728cb`): J153 printed LINK for any Q=1 term; now it prints LINK only for
  integers (P=0) and SYMB for alphanumeric terms. regress 9/9.

### 5. First light

`drivers/write-a.card` gives D1 (the writer) a one-letter image, [Q1]. D1 → D2 → D0 sorts it
through U1 to X1 → L1, and E4 prints:

```
A
RUN ENDED at cycle 789
```

To our knowledge this is the first execution of EPAM II code. Tag: `epam-first-light`.
