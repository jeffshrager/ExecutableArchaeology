## Work Done

### 1. Survey: what the faithful deck needs

`ysimon.card` (the faithful transcription) uses J10 J100 J117 J123 J125 J126 J129 J152 J153
J154 J155 J157 J160 J161 J2 J30 J50 J6 J60 J64 J65 J68 J7 J71 J75 J8 J81 J82 J9. The Lisp
IPL-V lacked **J123, J129 and J153**, and its `numget` called `break` on any negative number,
which the program needs: C0 and C2 count by negating with J123 and tallying up to zero.

A probe run in the scratchpad (stub J's and a patched `numget` loaded on top of the
interpreter, `iplv.lisp` untouched) showed that **the faithful deck otherwise runs unmodified**
and that Simon's own printer C3 prints whole sentences. None of the five 1620 workarounds is
needed: the Lisp IPL-V has a working J82, treats the undefined L1/L2 as empty lists, and has
the print-line routines.

### 2. Decision (discussed with Jeff)

J129 can't reasonably be written in IPL (the interpreter has no J112 multiply either), so the
missing J's go into the interpreter. Jeff agreed the changes are safe for the other programs:
none of LT, the Heuristic Coder, the annexer or the tests uses J123/J129/J153, and removing
the negative-number `break` can't change a run that already completed. Jeff chose option (a):
**J129 should copy Beyer's 1620 JJ129 exactly**, so the two interpreters can be cross-checked.

### 3. Beyer's J129, read from the SPS source

`IPL-V-Interpreter-Mod-3-4.sps`, JJ129 (lines ~2316-2332), with DOIT/GET2 and the 12-digit
cell layout (P Q SYMB LINK; an integer is `01` + 10 digits):

```
TF  H0-5,W10-5     push the seed name (from W10)
BTM GET2           D5 := seed value, D6 := n
BTM JJ90           new cell for the output
MM  D5,9013        product of seed x 9013 in 80-99
SF 90 / TF D5,99   D5 := low 10 digits          -> s' = s*9013 mod 10^10
M   D5,D6          s' x n, 20 digits in 80-99
TF  H0-5,89        output := high 10 digits     -> floor(s'*n / 10^10)
TF  W10-5,D5       seed cell := s'
```

### 4. Interpreter changes (`IPL-V/iplv.lisp`, logged in `CHANGES_FROM_UPSTREAM.md`)

- `numget` returns negative numbers (it used to `break`).
- **J123** negates (0) in place, with no pop. Lisp has no −0, so the manual's "zero into minus
  zero" is not represented.
- **J129** as above, integers only, and sets H5+.
- **J153** prints the data term's value alone on a line.

Regression: LT 24/24, the Heuristic Coder `run/t1*.txt` and the annexer unchanged,
`tests/Acker.Ipl` = 125, `tests/Ackermann.liplv` = 61. LT's `.out` differed only in compile
timestamps (reverted).

### 5. `SimonYngve2/`

A copy of `SimonYngveSentenceGenerator/` without `retro1620/`, `ysimon-fixed.card` or
`ysimon-fast.card`, which remain in the original directory.

- `ysimon.card`: identical to the original faithful deck.
- `run.sh [--count N] [--seed N]` copies the deck to `ysimon-run.card`, setting N20/N0 if
  asked, runs `run-yngve.lisp` (about 3 s), and writes `yngve-lisp.out` (raw),
  `printout.txt` (only C3's J155 lines) and `sentences.txt`.
- `decode.py` produces the same format as `retro1620/decode.py`. Lessons from writing it:
  - J155 output is `::::…: ` + the 80-column buffer. A sentence's first line has its text in
    col 12; continuation lines start in col 11, because C3 enters a space (`10N1 J161`) before
    each word but not after an overflow.
  - A line break may fall between two words (`AND` / `BIG`) or between the fragments of one
    word (`FIRE` / `BOX`, `OILE` / `D`), and trailing blanks don't tell which: `FIRE` was
    entered with a trailing blank. The decoder joins two pieces without a space when the
    result is a word spelled by the deck's B lists.
  - The trace starts with `A0`, which the 1620 printed as a bare `A` and its decoder skipped,
    so it is dropped.
- `README.md` is new. In `Yngve_guide.md`, "Running It Today" is rewritten for the Lisp IPL-V,
  with two DON'T MISS boxes (the cross-check, and the 1962 seed draws), and the provenance
  notes are updated.
- The original guide's line "Lisp IPL-V lacks J123, J129, J153" now points to `SimonYngve2/`.

### 6. Result

**With seed 53 the Lisp run's `sentences.txt` is byte-identical to
`SimonYngveSentenceGenerator/retro1620/sentences.txt`**: the same 20 sentences, with the
same derivations random draw for random draw. Beyer's 1963 interpreter (emulated) and a Lisp
interpreter written from the manual agree on every step, which also confirms the reading of
JJ129.
