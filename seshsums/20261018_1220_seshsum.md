## Efficiency and robustness

- `39b70d0`: `defj` records each J's argument list in `*jfn-plists*` (`args`). The executor
  fetches exactly that many H0 entries (`getstack "H0" n`). Before, it used
  `function-lambda-expression` and walked the whole H0 stack on every J call. (Jeff asked how
  this would be done; the answer was the existing plist, not a new alist.)
  - Test-only build at `(debug 1)`: the old executor crashes ("invalid number of arguments: 0").
    The new one runs LT 24/24 and Yngve identically.
  - But 83 LT effort figures differ by a constant 28 cycles within one theorem. So something else
    still depends on `(debug 3)`, and the declaim stays. Unexplained; possibly `eq` on string
    constants.
- `03bad4b`: `*card-cycles.ids-executed*` keeps the last 10,000 entries (trimmed in batches) and
  is cleared by `reset!`. It had reached 952,340 entries for LT and was never cleared.
  `backtrace!` still works.
- `fc6b33f`: the default `:adv-limit` is 10^8 for `load-ipl` (was 100) and `run` (was 1000).
- Skipped: the per-cycle trace scan, which is under 1% in the profile.

**Profile of LT** (sb-sprof; 2.6 s, 649,967 cycles, 351 MB consed):
- About 25% is J68's last-cell case, which scans the entire symbol table for the predecessor.
- About 24% is `puthash` into the symbol table. Every push and new cell adds an entry, and
  nothing is reclaimed.

Both are in the memory model (plan Steps 4-5). Today's changes gained only about 2%.
